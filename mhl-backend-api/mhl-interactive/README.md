# МХЛ — интерактивный веб-проект с backend API

Учебный многостраничный проект на HTML, CSS и JavaScript (ES modules) с собственным backend на Node.js. Проект демонстрирует обмен данными между браузером и сервером через HTTP API. Данные backend сохраняются в `server/data/db.json`.

## Запуск

1. Установите Node.js (рекомендуется актуальная LTS-версия).
2. Распакуйте архив и откройте папку `mhl-interactive` в VS Code.
3. В терминале выполните `npm install` (в проекте нет внешних npm-зависимостей; команда подготовит npm-проект).
4. Запустите сервер: `npm start`.
5. Откройте `http://localhost:3000`.

Важно: для работы API открывайте сайт именно через Node-сервер по адресу `http://localhost:3000`, а не через Live Server и не через `file://`.

## Структура

- `index.html`, `pages/` — страницы проекта.
- `css/style.css` — стили, адаптивная вёрстка.
- `js/app.js` — логика интерфейса и обработчики событий.
- `js/data.js` — демонстрационные исходные данные команд и матчей.
- `js/api.js` — клиентский модуль для HTTP-запросов к backend.
- `js/notifications.js` — интеграция с браузерным Notification API.
- `server.js` — backend и раздача статических файлов.
- `server/data/db.json` — серверное хранилище избранного, заказов и обращений.
- `assets/images/` — изображения команд.

## Реализованные API endpoints

| Метод | Endpoint | Назначение |
|---|---|---|
| GET | `/api/health` | Проверка доступности backend |
| GET | `/api/matches` | Получить матчи |
| GET | `/api/teams` | Получить команды |
| GET | `/api/favorites` | Получить избранные команды |
| POST | `/api/favorites` | Добавить команду в избранное (`{ "teamId": "dynamo-m" }`) |
| DELETE | `/api/favorites/:teamId` | Удалить команду из избранного |
| POST | `/api/orders` | Сохранить заказ билета |
| POST | `/api/support` | Сохранить обращение в поддержку |

## Как API используется на странице

1. При открытии любой страницы `js/app.js` вызывает `GET /api/matches`, `GET /api/teams` и `GET /api/favorites`. Полученные с сервера данные используются при построении карточек матчей, списка команд и страницы избранного.
2. При добавлении команды отправляется `POST /api/favorites`; при удалении — `DELETE /api/favorites/:teamId`. Список и счётчик избранного обновляются ответом сервера.
3. При оформлении билета отправляется `POST /api/orders`. Сервер сохраняет заказ и возвращает номер заказа; он показывается в окне подтверждения.
4. Форма поддержки отправляет `POST /api/support`; интерфейс показывает номер сохранённого обращения.

Клиентские запросы собраны в `js/api.js`, серверная маршрутизация и чтение/запись данных — в `server.js`. При ошибке запроса пользователь видит сообщение, а в консоли появляется диагностическая запись. При недоступности backend приложение показывает демонстрационные данные команд и матчей из `js/data.js`.

## Пример проверки API вручную

При запущенном сервере откройте DevTools → Console или используйте терминал:

```bash
# GET: получить список матчей
curl http://localhost:3000/api/matches

# GET: получить команды
curl http://localhost:3000/api/teams

# POST: добавить команду в избранное
curl -X POST http://localhost:3000/api/favorites \
  -H "Content-Type: application/json" \
  -d '{"teamId":"dynamo-m"}'

# GET: проверить избранное
curl http://localhost:3000/api/favorites

# POST: создать демонстрационный заказ
curl -X POST http://localhost:3000/api/orders \
  -H "Content-Type: application/json" \
  -d '{"matchId":"m1","seat":{"sector":1,"row":3,"seat":4,"price":1500},"customerName":"Test User","customerEmail":"test@example.com"}'
```

## Безопасность и ограничения учебного прототипа

- Платёж не проводится. Номер карты, срок действия и CVV не отправляются и не сохраняются на backend; сервер получает только имя, email, матч и выбранное место.
- JSON-файл подходит для демонстрации, но не рассчитан на конкурентную нагрузку и production-использование. В реальном сервисе нужны база данных, авторизация, защита персональных данных, валидация и платёжный провайдер.
- Notification API сохранён: уведомление показывается по нажатию пользователя, если браузер поддерживает API и дал разрешение.

## Соответствие критериям задания

- **GET:** реализованы `GET /api/matches`, `/api/teams` и `/api/favorites`.
- **POST/PUT/PATCH:** реализованы `POST /api/favorites`, `/api/orders` и `/api/support` (также `DELETE` для избранного).
- **Данные сервера используются на странице:** список матчей, команды, избранное и подтверждения заказов/обращений формируются на основе ответов API.
- **Структура:** клиентские запросы вынесены в `js/api.js`, серверная логика — в `server.js`.
- **Ошибки:** API возвращает JSON с сообщением и HTTP-статусом; клиент обрабатывает неуспешные ответы и недоступность сервера.
