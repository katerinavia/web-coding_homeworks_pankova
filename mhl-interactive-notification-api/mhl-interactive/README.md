# МХЛ — интерактивный прототип

Учебный многостраничный проект на HTML, CSS и JavaScript (ES modules), сделанный по экранам макета Figma и PDF. Это демонстрационный прототип: платёжные данные никуда не отправляются, реальное списание средств не выполняется.

## Как запустить

1. Распакуйте папку `mhl-interactive` целиком.
2. Откройте её в Visual Studio Code через **File → Open Folder**.
3. Запустите локальный сервер, например расширением **Live Server** (кнопка **Go Live**). Не открывайте HTML через `file://`: браузер может блокировать ES modules при запуске напрямую с диска.
4. Откройте главную страницу `index.html` через Live Server.

## Структура

- `index.html` — билеты и список матчей.
- `pages/matches.html` — выбор сектора и места.
- `pages/match.html` — проверка выбранного билета.
- `pages/search.html` — форма оплаты.
- `pages/team.html` — список команд; при переходе по карточке показывает экран выбранной команды.
- `pages/favorites.html` — избранные команды и пустое состояние.
- `pages/arena.html` — ближайший домашний матч команды.
- `css/style.css` — общие стили, CSS-переменные, Flexbox/Grid и адаптивные правила.
- `js/data.js` — данные команд и матчей в массивах объектов.
- `js/app.js` — рендер DOM, обработчики событий, модальные окна и состояние приложения.
- `js/notifications.js` — отдельный модуль интеграции с браузерным Notification API и обработки ошибок.
- `assets/images/` — логотипы команд, извлечённые из исходного проекта.

## Реализованный функционал

1. **Фильтр по городу:** кнопка «Город» открывает модальное окно выбора «Москва» или «Санкт-Петербург». Список матчей перестраивается по выбору. «Сбросить фильтры» возвращает полный список.
2. **Избранное:** команды добавляются и удаляются кнопкой-сердцем на экране «Команды» или кнопкой в карточке команды. Состояние сохраняется в `localStorage` и остаётся после перезагрузки. Страница «Избранное» динамически показывает сохранённые команды или пустое состояние.
3. **Покупка билета:** можно выбрать матч, сектор, ряд и место. Схема мест создаётся динамически на JavaScript; стоимость зависит от ряда (1000/1500/2000 ₽). Выбор сохраняется и отображается в резюме заказа.
4. **Ввод карты и оплата:** форма проверяет номер карты (16 цифр), срок действия, CVV, имя владельца и email. После корректного заполнения показывается модальное окно успешной оплаты. Это только учебная имитация, данные карты не отправляются и не сохраняются.
5. **Поддержка:** кнопки «Поддержка» в шапке и футере открывают модальное окно с телефоном и email. В нём есть форма вопроса; после отправки отображается подготовленное обращение и адрес поддержки. Для реальной отправки потребуется сервер или почтовый клиент.
6. **Обратная связь:** используются toast-сообщения, счётчик избранного и обновление элементов интерфейса без перезагрузки страницы.
7. **Notification API:** у каждой карточки матча есть кнопка «Уведомить». По нажатию приложение проверяет поддержку API и защищённый контекст, запрашивает разрешение пользователя при необходимости и показывает системное уведомление с командами, датой, временем и городом матча. Если браузер не поддерживает API, сайт открыт не через HTTPS/localhost или пользователь запретил уведомления, приложение показывает понятное сообщение и продолжает работать.

## Как выполнены критерии задания

- **Динамическое создание и изменение DOM:** карточки матчей и команд, список избранного, схема мест, уведомления и модальные окна создаются/обновляются через `innerHTML` и DOM API.
- **Данные в JS-структурах:** команды и матчи хранятся в массивах объектов в `js/data.js`; выбор города, матча, места и избранного хранится отдельно.
- **Обработка событий:** делегирование `click`, обработка `submit`, `input` и `keydown` (Escape для закрытия модального окна).
- **ES modules:** `app.js` импортирует данные из `data.js` и функцию уведомлений из `notifications.js`; HTML подключает приложение через `<script type="module">`.
- **Обработка ошибок API:** проверяются наличие `Notification`, `isSecureContext`, разрешение пользователя и исключения при создании уведомления. При ошибке выводится понятное сообщение; остальной интерфейс остаётся доступен.
- **Консоль:** проект не использует сторонние библиотеки или сетевые запросы. Синтаксис JavaScript проверяется командой `node --check`. Для ручной проверки откройте DevTools → Console и пройдите основные сценарии.
- **Адаптивность:** CSS media queries для экранов планшета и мобильного телефона.

## Проверка Notification API

1. Запустите сайт через VS Code Live Server (обычно `http://127.0.0.1:5500`) или другой локальный сервер. Не используйте `file://`.
2. Нажмите «♧ Уведомить» на любой карточке матча.
3. При первом использовании разрешите уведомления в браузере. После разрешения должно появиться системное уведомление с данными матча.
4. Повторите проверку с заблокированными уведомлениями: приложение должно показать сообщение о запрете, а страница продолжить работать.
5. Чтобы повторить запрос разрешения после блокировки, откройте настройки сайта в браузере и сбросьте разрешение вручную.

**Важно:** это демонстрация уведомления по действию пользователя, а не автоматическое напоминание в момент начала матча. Автоматические уведомления при закрытом сайте требуют Service Worker, push-сервера и дополнительной настройки. В учебных данных даты матчей могут быть прошедшими.

## Примечания

- Фильтр по городу и избранное хранят состояние в `localStorage` браузера.
- Даты и команды оставлены такими, как в учебном макете.
- Авторизация и настоящая платёжная система не реализованы, поскольку они требуют серверной части и выходят за рамки клиентского прототипа.
